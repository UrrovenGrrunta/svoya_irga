# Своя игра

**Project status: Frozen**

«Своя игра» — небольшое приложение для проведения викторин в компании друзей. Ведущий управляет партией через веб-интерфейс, а игроки подключаются и отвечают через Telegram-бота.

Проект предназначен для одной локальной игры на один вечер и пока не рассчитан на публичное использование или несколько одновременных партий.

## Состояние проекта

Проект заморожен. Планируется вернуться к разработке позже.

Текущая цель после возобновления разработки — создать минимальную работающую версию, в которой игроки смогут подключиться к партии, получить вопрос, нажать кнопку «Ответить» и получить или потерять очки после решения ведущего.

## Интерфейсы

У приложения две стороны:

- Telegram-бот для игроков;
- веб-пульт ведущего.

### Telegram-бот

Telegram-бот используется для:

- подключения к партии;
- получения вопросов;
- отображения кнопки «Ответить»;
- уведомления игрока о результате ответа;
- отображения текущего счёта.

Взаимодействие с ботом происходит в личных сообщениях.

### Веб-пульт ведущего

Веб-пульт используется для:

- создания и запуска партии;
- просмотра подключённых игроков и их очков;
- выбора темы и стоимости вопроса;
- просмотра текста вопроса и правильного ответа;
- определения очерёдности игроков;
- подтверждения правильного или неправильного ответа;
- завершения вопроса и всей партии.

## Подключение игроков

1. Ведущий создаёт новую игру.
2. Приложение генерирует код и ссылку для подключения.
3. Ведущий передаёт ссылку игрокам.
4. Игрок открывает ссылку и запускает Telegram-бота.
5. Бот получает команду с кодом игры, например:

   ```text
   /start AB12CD
   ```

6. Игрок присоединяется к активной партии.
7. Ведущий видит подключившегося игрока в веб-пульте.
8. Когда все игроки подключились, ведущий начинает игру.

## Игровой процесс

После начала партии ведущий видит таблицу тем и стоимости вопросов.

1. Игрок вслух называет тему и стоимость вопроса.
2. Ведущий выбирает соответствующую ячейку.
3. Вопрос появляется в веб-пульте и отправляется всем игрокам в личные сообщения.
4. Начинается общий таймер на 30 секунд.
5. Игроки могут нажать кнопку «Ответить».
6. Право ответа получает игрок, нажавший кнопку первым.
7. Остальные игроки временно не могут отвечать.
8. Игрок произносит ответ вслух.
9. Ведущий нажимает «Верно» или «Неверно».

### Правильный ответ

Если ответ правильный:

- стоимость вопроса прибавляется к счёту игрока;
- правильный ответ показывается игрокам;
- вопрос закрывается;
- соответствующая ячейка становится недоступной.

### Неправильный ответ

Если ответ неправильный:

- стоимость вопроса вычитается из счёта игрока;
- игрок больше не может отвечать на этот вопрос;
- возможность ответа открывается остальным игрокам;
- общий таймер продолжает отсчёт с оставшегося времени.

### Завершение вопроса

Вопрос закрывается, если:

- один из игроков дал правильный ответ;
- истекло время;
- все игроки ответили неправильно;
- ведущий досрочно завершил вопрос.

После закрытия вопроса игрокам показывается правильный ответ, а сыгранная ячейка становится недоступной.

## Завершение игры

Игра заканчивается, если:

- сыграны все вопросы;
- ведущий досрочно завершил партию.

После завершения отображаются итоговые результаты. Победителем становится игрок с наибольшим количеством очков.

## Основные правила

- Одновременно может быть активна только одна партия.
- К партии могут подключаться только игроки с правильным кодом.
- Один вопрос нельзя выбрать повторно.
- Отвечать могут только подключённые игроки.
- Право ответа одновременно может принадлежать только одному игроку.
- Игрок не может повторно отвечать на тот же вопрос после неправильного ответа.
- Изменить счёт может только ведущий.
- После закрытия вопроса нажатия игроков больше не принимаются.
- Счёт игрока может быть отрицательным.

## Хранение данных

Для хранения данных используется SQLite.

В базе данных планируется хранить:

- наборы вопросов;
- темы;
- тексты вопросов и правильные ответы;
- стоимость вопросов;
- сведения об активной партии;
- подключённых игроков;
- текущий счёт;
- состояние и результаты вопросов.

JSON в дальнейшем может использоваться для импорта и экспорта наборов вопросов.

## Архитектура

Проект разделяется на игровую логику и внешние интерфейсы.

### Игровая логика

Игровая логика отвечает за:

- состояние партии;
- игроков и их очки;
- темы и вопросы;
- очерёдность ответов;
- проверку допустимости действий;
- начало и завершение вопросов;
- начало и завершение партии.

Игровая логика не должна зависеть от Telegram, веб-интерфейса или конкретной базы данных.

### Внешние интерфейсы

К внешним частям приложения относятся:

- Telegram-бот для игроков;
- веб-пульт ведущего;
- SQLite для хранения данных.

Telegram-бот и веб-пульт используют общую игровую логику.

## Планируемые технологии

- Python 3.12 или новее;
- aiogram 3 для Telegram-бота;
- FastAPI для веб-приложения;
- SQLite для хранения данных;
- Hatchling для сборки Python-проекта.

## За пределами первой версии

В первую версию пока не входят:

- несколько одновременных партий;
- публичная регистрация ведущих;
- сложная система авторизации;
- финальный раунд;
- вопросы-аукционы;
- «Кот в мешке»;
- вопросы с изображениями, аудио или видео;
- редактор наборов вопросов;
- автоматическая проверка произнесённых ответов;
- Telegram Mini App;
- поддержка PostgreSQL.
